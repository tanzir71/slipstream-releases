Slipstream / Privacy

Privacy

Slipstream is local-first. What you record, transcribe and edit stays on your device. There are no accounts, no analytics and no uploads.

Last updated November 2026

  • Your recordings, audio, transcripts and projects never leave your device.
  • No accounts, no telemetry, no analytics, no ads, and no cookies set by Slipstream.
  • Slipstream Web goes online only to download its transcription library and AI models, each the first time you use the feature that needs it.

What runs on your device

  • Recording. Your browser or operating system captures the screen, window or tab, the camera and the microphone, and Slipstream writes them straight to local storage.
  • Transcription. Whisper runs inside Slipstream Web (WebGPU, or WebAssembly as a fallback) or inside the desktop app. Your audio is processed in place and never sent anywhere. You can also import an SRT or VTT file and skip the model entirely.
  • Editing. Cuts, filler and pause removal, zooms, camera layouts, backgrounds and captions are computed locally.
  • Export. Videos are encoded on your device with WebCodecs in the browser, or with the desktop engine. Finished files are saved wherever you choose.
  • Project storage. Slipstream Web keeps projects in your browser’s own storage: project data in IndexedDB, and recordings and media in the Origin Private File System (OPFS). They stay in that browser profile on that device until you delete the project or clear the site’s data. The desktop apps save projects to folders on your computer.

The only network requests Slipstream Web makes

Opening the web app loads its own files from this site. Apart from that, it makes the requests below, and only when you start the feature that needs them. Before a model downloads, the app shows its size. Your browser caches what it downloads, so later sessions don’t fetch it again.

These requests download files to your device. They never include your recordings, audio, transcripts or project data. As with any web request, the server sees your IP address, your browser’s user agent and which file was requested. If your browser provides its own on-device language model, the copilot can use that instead. The browser manages that download.

Optional cloud models with your own key

Everything above works without an account or a key. If you choose to, you can add your own key for a cloud provider in the copilot’s cloud settings. Nothing is sent until you add a key, tick the consent box and then use the feature, and every cloud action is labelled Cloud in the app.

You can also share an export through your own storage: set up an S3-compatible bucket (AWS S3, Cloudflare R2, Backblaze B2, MinIO and others) and Slipstream uploads the finished video straight from your device to that bucket and makes a link that expires within seven days. Only the files you choose to share are uploaded, only to the bucket you configured, and the access keys stay on your device.

Recorded video and audio are never sent. Keys are stored only on your device (in this browser’s storage, or the system keychain in the desktop apps) and are never written into projects, .slipstream files or exports. Usage is billed by the provider under your account and covered by their privacy policy. You can remove all keys from the same settings at any time.

The desktop apps

  • No accounts, no telemetry and no uploads. Recording, transcription, editing and export run on your computer.
  • While you record the whole screen, the desktop apps note where the pointer is and when you click, so zooms can follow your clicks. Keystrokes aren't recorded, except by the macOS app's optional keystroke overlay: it only works after you grant Accessibility access, draws the keys you press into your video, and keeps them in that project's folder on your Mac (never in .slipstream files). Pointer positions stay with that project on your device, and in .slipstream files you export from it.
  • On Windows and Linux, the app can download the FFmpeg and whisper runtimes (whisper.cpp) from GitHub or Hugging Face when you choose to install them. It shows the size and the host first, checks each download against a pinned SHA-256 before unpacking it, and sends nothing about you or your recordings. You can also install from a file you already have. The macOS app uses Apple’s built-in frameworks and downloads no runtime.
  • Update checks happen only when you ask (Check for updates). The app then reads latest.json from the project’s GitHub Releases (one request to github.com, no cookies). If you choose to install an update, it’s downloaded from GitHub (served via githubusercontent.com) and checked before it installs: on Windows and Linux against the updater signature, on the Mac against its SHA-256 and the same signing certificate as the copy you have. Nothing else is sent.
  • Installers are served from this site or from GitHub Releases, with SHA-256 checksums so you can verify them.

This website

This site and Slipstream Web are static files hosted on GitHub Pages. As with any web host, GitHub receives ordinary request data for each page and file: your IP address, user agent and the address requested. GitHub handles that data under the GitHub General Privacy Statement. The site serves its fonts and images itself, runs no analytics or tracking scripts, and sets no cookies of its own.

Links to other sites (GitHub, Unsplash, tanziro.com, Buy Me a Coffee) are plain links. Nothing loads from them until you click, and their own privacy policies apply once you do.

Your controls

  • Delete a project in Slipstream Web to remove its media from browser storage. Clearing this site’s data in your browser settings removes every project and every cached model.
  • Import captions as SRT or VTT if you would rather not download a speech model.
  • Leave speaker labels, translation and the copilot off, and those models are never fetched.
